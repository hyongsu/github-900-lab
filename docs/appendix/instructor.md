# 강사용 진행 메모

수업 전 준비와 당일 진행에서 놓치기 쉬운 것을 모았습니다.

## 수업 전날까지

- [ ] `skilleat-labs/lunch-picker-starter` 리포지토리를 만들고 이 가이드의 `starter/` 폴더 내용을 그대로 올린다
- [ ] Starter의 **Settings** → **General** → **Template repository** 체크 (이걸 켜야 **Use this template** 버튼이 생긴다)
- [ ] 강사 계정이 아닌 **다른 계정**으로 1교시 실습 1-2를 끝까지 해 본다 (템플릿 복사 → Pages 켜기 → Run workflow → 웹페이지 확인)
- [ ] 같은 계정으로 3교시 PR을 하나 열어 **메뉴 데이터 검사**가 도는지 확인한다
- [ ] 수강생 사전 안내: GitHub 계정, 노트북, 회사망 접속 확인, 휴대폰 인증 앱
- [ ] 팀 편성표 (21명: 4인 3팀 + 3인 3팀), 역할 카드 인쇄
- [ ] 6교시 변경 요청 CR-001 발표 슬라이드

## 교시별 주의할 점

**1교시**
: 실습 1-1 직전에 강사 화면으로 실제 대시보드와 내 프로필(`github.com/아이디`)을 30초 보여 준다(장표는 단순화한 그림). 가운데 Copilot 입력 칸은 오늘 쓰지 않는다고 짚는다. 실습 1-1은 빈 리포지토리 `my-first-repo`에서 "고치고 Commit changes를 누르면 커밋이 늘어난다"만 체감시키는 단계라, Add README를 켜는지 꼭 확인한다. 실습 1-2에서 템플릿으로 만든 직후 **웹페이지 배포가 실패**하는 게 정상이다. 수강생이 놀라지 않게 미리 말한다. Pages를 켜고 Run workflow로 다시 돌린다.

**2교시**
: 멘션 실습(2-4 STEP 6)에서 혼자 앉은 수강생은 강사 아이디를 멘션한다. 화면에 띄울 아이디는 조직 `skilleat-labs`가 아니라 **강사 개인 계정 아이디**여야 한다(조직 이름을 멘션하면 알림을 받을 사람이 없다). 멘션 실습은 옆 사람 아이디가 필요하다. 1교시 끝에 서로 아이디를 교환해 두면 빠르다.

**3교시**
: 짝 초대 수락에 시간이 걸린다. 3교시 시작하자마자 3-1(초대)부터 시킨다. 충돌 실습(3-4)에서는 **price-b 분기를 main에서 만들어야** 충돌이 난다. price-a에서 만들면 충돌이 안 난다.

**4교시**
: 팀 Projects는 PM 개인 계정 소유라 **Manage access로 팀원을 따로 추가**해야 한다. 리포지토리 초대와 별개라는 점을 꼭 짚는다.

**5교시**
: BA가 만드는 스토리 중 **대표 스토리** `[스토리] 새 메뉴 2개를 추가해 선택지 늘리기`가 빠지지 않았는지 꼭 확인한다. 6교시 구현과 감사가 이 이슈로 이어진다. Projects 보드는 `MVP 보드`(MoSCoW)와 `진행 보드`(Status) 두 개를 만들게 한다. 개발자 역할은 앞 역할을 기다리는 시간이 길다. 역할 카드의 "기다리는 동안 할 일"(회의록 읽고 질문 메모)을 시킨다. Must가 3개를 넘는 팀이 많다. PO에게 "MVP는 작아야 한다"를 다시 짚는다.

**6교시**
: 6-1은 대표 스토리를 구현한다. 초록 체크가 떠도 BA는 인수 조건으로, PO는 배포된 화면에서 다시 확인하게 한다(비빔밥 혼밥 가능, 예산 10000에 마라탕 보임). 미션 6-1이 시작되고 15분쯤 지나면 **CR-001을 발표**한다. 개발자가 delivery 값을 `"yes"`처럼 글자로 쓰면 자동 검사가 실패한다. 실패를 보고 고치는 경험 자체가 학습이다.

**7교시**
: Codespace 생성에 1~2분 걸린다. 설명 시작 전에 먼저 만들어 두게 한다. 분기 보호 설정은 **PO 계정의 Settings에서만** 할 수 있다. 수업 끝에 Codespace를 삭제하도록 안내한다.
