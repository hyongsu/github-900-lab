# 1교시 혼자 해보기와 확인 퀴즈

**소요 시간** 혼자 해보기 10분, 확인 퀴즈 5분  **실습 장소** 개인 연습 리포지토리 `lunch-practice`  **관련 교안** [1교시 교안](index.md)

## 혼자 해보기 { #practice }

!!! abstract "목표"
    - `site/menus.json`에 내가 좋아하는 메뉴 1개를 추가하고 커밋합니다.
    - menus.json 한 파일의 History에서 "가격을 바꾼 커밋"을 찾고, 새 파일 `docs/my-note.md`를 만들어 해시 7자리를 적습니다.

따라하기에서 한 일을 이번에는 안내 없이 해 봅니다. 막히면 아래 힌트를 1번부터 하나씩 열어 보세요.

### 과제 1. 내가 좋아하는 메뉴 추가하기

- 메뉴 이름, 종류, 가격, 거리, 혼밥 가능 여부는 마음대로 정합니다.
- 기존 6개 메뉴와 **이름이 겹치면 안 됩니다.**
- `비빔밥`은 고르지 않습니다. 3교시 실습 3-2에서 모두 함께 추가할 메뉴라서, 지금 넣으면 그때 이름이 겹칩니다.
- 커밋 메시지는 무엇을 했는지 알 수 있게 씁니다.
- 커밋 후 1~2분 뒤 웹페이지에 내 메뉴 카드가 보여야 합니다.

메뉴 한 줄의 항목은 아래와 같습니다.

| 항목 | 뜻 | 값의 모양 | 예 |
|---|---|---|---|
| `name` | 메뉴 이름 | 큰따옴표로 감싼 글자 | `"칼국수"` |
| `category` | 종류 | 큰따옴표로 감싼 글자 | `"한식"` |
| `price` | 가격(원) | 따옴표 없는 숫자, 쉼표 없이 | `8000` |
| `distance` | 회사에서 거리(미터) | 따옴표 없는 숫자 | `250` |
| `solo` | 혼밥 가능 | `true` 또는 `false` (따옴표 없음) | `true` |

### 과제 2. 가격을 바꾼 커밋 찾기

- 이번에는 리포지토리 전체가 아니라 **menus.json 한 파일만의 History**에서 실습 1-3에서 김치찌개 가격을 바꾼 커밋을 찾습니다.
- **Add file** → **Create new file**로 `docs` 폴더 안에 새 파일 `docs/my-note.md`를 만들고, 그 커밋의 해시 7자리를 한 줄로 적어 커밋합니다.

!!! note "파일 하나의 History는 언제 쓰나요?"
    리포지토리 전체 커밋 목록에는 모든 파일의 커밋이 섞여 나옵니다. 파일 화면 위쪽의 **History** 버튼을 누르면 그 파일을 바꾼 커밋만 나옵니다. "이 데이터 언제부터 이렇게 바뀌었지?"라는 질문이 생기면 이 화면을 엽니다. 6교시 이력 감사에서 Blame(줄별 이력)과 함께 다시 씁니다.

### 완료 조건

- [ ] `site/menus.json`에 메뉴가 7개 있습니다.
- [ ] 웹페이지에 내가 추가한 메뉴 카드가 보입니다. (메뉴가 하나도 안 보이면 쉼표 실수입니다)
- [ ] 커밋 메시지가 `Update menus.json`이 아니라 무엇을 했는지 알 수 있는 문장입니다.
- [ ] menus.json의 History에 커밋이 3개(`Initial commit`, 가격 수정, 내 메뉴 추가) 보입니다.
- [ ] `docs/my-note.md` 파일이 있고, 가격을 바꾼 커밋의 해시 7자리가 적혀 있습니다.

??? tip "힌트 1"
    **site** → **menus.json** → 연필 아이콘으로 편집합니다. 새 메뉴는 마지막 메뉴(`순두부찌개`) **아래**에 한 줄로 추가합니다. 해시는 menus.json 화면 위쪽 오른편의 시계 아이콘 **History** 버튼에서 찾습니다. 새 파일은 리포지토리 첫 화면의 **Add file** → **Create new file**에서 만듭니다.

??? tip "힌트 2"
    JSON에서는 메뉴와 메뉴 사이를 **쉼표**로 구분하고, **마지막 메뉴 뒤에는 쉼표가 없어야** 합니다. 그래서 마지막에 메뉴를 추가하면 두 군데를 고쳐야 합니다.

    1. 원래 마지막이던 `순두부찌개` 줄 끝 `}` 뒤에 쉼표 `,`를 붙입니다.
    2. 그 아래 새 줄에 내 메뉴를 쓰고, 끝에는 쉼표를 붙이지 않습니다.

??? tip "힌트 3"
    순두부찌개 줄부터 끝까지가 이렇게 되면 됩니다. `칼국수` 줄을 내 메뉴로 바꿔 쓰세요.

    ```json
      { "name": "순두부찌개", "category": "한식", "price": 8500, "distance": 350, "solo": true },
      { "name": "칼국수", "category": "한식", "price": 8000, "distance": 400, "solo": true }
    ]
    ```

    해시는 History 목록에서 `김치찌개 가격 9500원으로 수정` 줄 오른쪽의 7자리입니다. 그 옆 복사 아이콘을 누르면 40자리 전체가 복사되니, 붙여 넣은 뒤 앞 7자리만 남깁니다.

    새 파일 이름 칸(**Name your file...**)에는 `docs/my-note.md`를 입력합니다. `docs/`까지 입력하는 순간 슬래시가 폴더 구분으로 바뀌어 `lunch-practice / docs /` 모양이 되고, 칸에는 `my-note.md`만 남습니다. GitHub 웹에서는 파일 이름 앞에 `폴더/`를 붙여 폴더 안에 파일을 만듭니다.

??? success "정답 예시"
    **과제 1** `site/menus.json` 전체 (칼국수를 추가한 경우)

    ```json
    [
      { "name": "김치찌개", "category": "한식", "price": 9500, "distance": 300, "solo": true },
      { "name": "짜장면", "category": "중식", "price": 8000, "distance": 450, "solo": false },
      { "name": "돈카츠", "category": "일식", "price": 11000, "distance": 600, "solo": false },
      { "name": "샐러드볼", "category": "양식", "price": 10500, "distance": 200, "solo": true },
      { "name": "쌀국수", "category": "아시안", "price": 9500, "distance": 700, "solo": false },
      { "name": "순두부찌개", "category": "한식", "price": 8500, "distance": 350, "solo": true },
      { "name": "칼국수", "category": "한식", "price": 8000, "distance": 400, "solo": true }
    ]
    ```

    커밋 메시지:

    ```text
    메뉴에 칼국수 추가
    ```

    **과제 2** 새 파일 `docs/my-note.md` 내용 (해시는 사람마다 다릅니다)

    ```markdown
    # 내 메모

    - 김치찌개 가격을 바꾼 커밋: 3f9a1c2
    ```

    커밋 메시지:

    ```text
    수업 메모 파일 추가
    ```

??? failure "커밋했는데 웹페이지에 메뉴가 하나도 안 보입니다"
    menus.json이 JSON 형식에 맞지 않아 웹페이지가 데이터를 읽지 못한 것입니다. 가장 흔한 원인은 세 가지입니다.

    | 실수 | 예 |
    |---|---|
    | 순두부찌개 줄 끝 쉼표를 안 붙임 | `... "solo": true }` 다음 줄에 바로 `{ "name": ...` |
    | 내 메뉴 줄 끝에 쉼표를 붙임 | `... "solo": true },` 다음 줄이 `]` |
    | 따옴표, 중괄호를 빠뜨림 | `"name": 칼국수` (따옴표 없음) |

    menus.json을 다시 편집해 위 정답 예시와 비교하며 고친 뒤, 커밋 메시지 `메뉴 JSON 쉼표 수정`으로 다시 커밋합니다. 오늘 3교시부터는 이런 실수를 Pull Request 단계에서 자동 검사가 미리 잡아 줍니다.

## 확인 퀴즈 { #quiz }

??? question "Q1. 커밋(Commit)을 가장 잘 설명한 것은?"
    1. 파일을 다른 사람에게 보내는 것
    2. 누가, 언제, 왜 바꿨는지가 붙은 저장 기록 한 건
    3. 리포지토리를 새로 만드는 것
    4. 원본에 영향 없이 따로 작업하는 갈래

    **정답: 2**

    커밋은 그 순간 프로젝트 전체의 스냅샷에 작성자, 시간, 메시지, 앞 커밋 번호를 붙여 저장한 기록 한 건입니다. 4번은 분기(Branch)의 설명입니다.

??? question "Q2. 커밋 해시에 대한 설명으로 틀린 것은?"
    1. 커밋 내용으로 계산한 고유 번호다.
    2. 보통 앞 7자리만 써도 커밋을 구분할 수 있다.
    3. 같은 메시지로 커밋하면 해시도 같아진다.
    4. 중간 기록을 몰래 고치면 해시가 바뀌어 티가 난다.

    **정답: 3**

    해시는 메시지뿐 아니라 작성자, 시간, 스냅샷, 앞 커밋 번호까지 넣어 계산합니다. 같은 메시지라도 시간이나 작성자가 다르면 완전히 다른 해시가 나옵니다. 실습 1-3에서 옆자리 사람과 해시를 비교해 본 것처럼요.

??? question "Q3. 오늘 오전 실습처럼 GitHub 웹 화면에서 Commit changes를 누르면 커밋은 어디에 생기나요?"
    1. 내 컴퓨터의 로컬 리포지토리
    2. GitHub의 원격 리포지토리
    3. 브라우저에 임시 저장되었다가 push해야 GitHub에 올라감
    4. Starter 템플릿 리포지토리

    **정답: 2**

    웹 화면에서는 GitHub에 있는 원격 리포지토리를 바로 고치므로 push, pull 단계가 없습니다. 내 컴퓨터의 로컬 리포지토리에서 작업하고 push로 올리는 방식은 7교시에 터미널로 해 봅니다.

??? question "Q4. 다음 중 가장 좋은 커밋 메시지는?"
    1. `Update menus.json`
    2. `수정함`
    3. `김치찌개 가격 9500원으로 수정`
    4. `최종_진짜최종`

    **정답: 3**

    좋은 커밋 메시지는 무엇을(김치찌개 가격을) 어떻게(9500원으로) 바꿨는지 한 줄로 알려 줍니다. 이유가 필요하면 Extended description에 "식당 가격 인상 반영"처럼 덧붙입니다. 1번은 GitHub가 넣어 주는 기본값이라 어떤 내용이 바뀌었는지 알 수 없습니다.

## 다음 교시 시작 상태 확인

2교시를 시작하기 전에 아래 상태인지 확인합니다.

| 항목 | 이 상태여야 합니다 |
|---|---|
| 리포지토리 | 내 계정의 `lunch-practice` (Public). 웹페이지 `https://<내 아이디>.github.io/lunch-practice/`가 열립니다 |
| 현재 분기 | `main` (아직 다른 분기는 없습니다) |
| 남겨 둘 이슈, PR | 이슈와 PR은 아직 없습니다. 1교시 커밋(김치찌개 가격 수정, 내 메뉴 추가, `docs/my-note.md`)은 지우지 않습니다. 실습 1-1의 `my-first-repo`는 이후 쓰지 않습니다 |
| 데이터 상태 | README는 Starter 그대로입니다 (2교시에 꾸밉니다). `site/menus.json` 메뉴 6개 또는 7개 (혼자 해보기에서 메뉴를 추가했으면 7개). 김치찌개 가격 9500 (실습 1-3을 건너뛰었다면 9000). 어느 쪽이든 그대로 둡니다 |
| 다음에 열 화면 | `lunch-practice`의 **Code** 탭 첫 화면 (README). 2교시 실습 2-1에서 README를 꾸밉니다 |
