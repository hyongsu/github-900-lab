# 실습 2-2. 이슈 등록과 분류

!!! abstract "이번 실습에서 할 것"
    - 라벨 5개(`기능`, `질문`, `우선순위-상`, `우선순위-중`, `우선순위-하`)와 마일스톤 `MVP`를 만듭니다.
    - 킥오프 회의록에서 뽑은 요구 2개를 이슈로 등록하고 담당자, 라벨, 마일스톤을 붙입니다.
    - 라벨로 이슈를 걸러 보고, 이슈 하나를 닫아 봅니다.

**소요 시간** 약 7분  **실습 장소** 개인 연습 리포지토리 `lunch-practice`  **관련 교안** [2교시 교안](index.md#organize)

## 준비

- `lunch-practice` 리포지토리를 열어 둡니다.
- 다른 탭에 `docs/01_킥오프_회의록.md`와 `docs/00_현업요청.md`를 열어 두면 이슈 내용을 쓸 때 참고하기 좋습니다.
- 지금은 이슈가 하나도 없습니다. **Issues** 탭 옆 숫자가 없거나 0입니다.

## STEP 1. 라벨 만들기

GitHub는 리포지토리를 만들 때 `bug`, `documentation`, `enhancement` 같은 영어 기본 라벨 9개를 넣어 둡니다. 우리는 우리 팀이 쓸 한국어 라벨 5개를 새로 만듭니다.

1. 리포지토리 위쪽 탭에서 **Issues**를 클릭합니다.
2. 이슈 목록 위쪽, 검색창 오른편의 **Labels**(라벨) 버튼을 클릭합니다.
3. 기본 라벨 9개가 보입니다. 오른쪽 위 초록색 **New label**(새 라벨) 버튼을 클릭합니다.
4. 입력 줄이 펼쳐집니다. **Label name** 칸에 첫 번째 라벨 이름을 입력합니다.

    ```text
    기능
    ```

5. **Description**(설명) 칸에 설명을 입력합니다. (선택 항목이지만 써 두면 다른 사람이 헷갈리지 않습니다.)

    ```text
    새로 만들 기능 요구
    ```

6. **Color** 칸에 색 코드를 입력합니다. 왼쪽 색 상자를 누르면 추천 색 중에 고를 수도 있고, 새로고침 모양 버튼을 누르면 무작위 색이 나옵니다. 아래 표의 색을 그대로 써도 됩니다.
7. 초록색 **Create label** 버튼을 클릭합니다.
8. 3~7을 반복해 나머지 4개도 만듭니다.

| Label name | Description | Color (예시) |
|---|---|---|
| `기능` | 새로 만들 기능 요구 | `#0E8A16` (초록) |
| `질문` | 결정이 필요하거나 확인할 것 | `#D876E3` (보라) |
| `우선순위-상` | 가장 먼저 할 것 | `#B60205` (빨강) |
| `우선순위-중` | 그다음에 할 것 | `#FBCA04` (노랑) |
| `우선순위-하` | 여유 있을 때 할 것 | `#C5DEF5` (연파랑) |

복사용 라벨 이름:

```text
질문
```

```text
우선순위-상
```

```text
우선순위-중
```

```text
우선순위-하
```

확인: 라벨 목록 위쪽 숫자가 **14 labels**(기본 9개 + 새로 5개)이고, 목록에 5개 한국어 라벨이 보입니다.

!!! note "색은 왜 정하나요?"
    이슈 목록에서 라벨은 색깔 꼬리표로 보입니다. 우선순위처럼 단계가 있는 라벨은 빨강, 노랑, 연파랑처럼 강한 색에서 약한 색으로 맞춰 두면 목록만 훑어봐도 급한 일이 눈에 띕니다. 색은 나중에 **Edit**로 언제든 바꿀 수 있습니다.

## STEP 2. 마일스톤 MVP 만들기

**마일스톤**은 "이번 출시에 함께 내보낼 이슈 묶음"입니다. 첫 출시 묶음을 **MVP**(Minimum Viable Product, 쓸 수 있는 최소한의 첫 제품)라고 부릅니다.

1. 라벨 화면 위쪽에서 **Milestones**(마일스톤) 버튼을 클릭합니다. (Labels 버튼 바로 옆에 있습니다.)
2. 오른쪽 위 초록색 **New milestone**(새 마일스톤) 버튼을 클릭합니다.
3. **Title**(제목) 칸에 입력합니다.

    ```text
    MVP
    ```

4. **Due date**(마감일) 칸을 클릭하면 달력이 나옵니다. **오늘부터 일주일 뒤 날짜**를 고릅니다. (선택 항목입니다. 연습이니 아무 날짜나 괜찮습니다.)
5. **Description** 칸에 입력합니다.

    ```text
    첫 출시. 예산과 거리로 메뉴를 거르는 최소 기능
    ```

6. 초록색 **Create milestone** 버튼을 클릭합니다.

확인: 마일스톤 목록에 **MVP**가 보이고, 마감일과 `0% complete`, `0 open`, `0 closed`가 표시됩니다.

## STEP 3. 첫 번째 이슈 등록하기

현업 요청에서 "급한 순서로 1, 2번이 제일 급하다"고 한 요구 중 하나를 이슈로 만듭니다.

!!! note "웹페이지에 예산 칸이 이미 있는데 왜 이슈로 만드나요?"
    Starter 웹페이지에는 예산과 거리 칸이 이미 들어 있습니다. 그래도 현업이 요청한 요구는 이슈로 남깁니다. 이슈에는 **누가 왜 요청했는지(근거)**와 **무엇이 되면 끝인지(완료 조건)**가 기록되기 때문입니다. 화면에 기능이 있다고 끝이 아니라, 완료 조건을 하나씩 확인해야 끝입니다. 실습 2-4에서 이미 있는 기능(#5)을 완료 조건으로 확인하고 닫는 것도 해 봅니다.

1. 위쪽 탭에서 **Issues**를 클릭합니다.
2. 오른쪽 위 초록색 **New issue**(새 이슈) 버튼을 클릭합니다.
3. **Add a title**(제목) 칸에 입력합니다.

    ```text
    예산으로 메뉴 거르기
    ```

4. **Add a description**(본문) 칸에 아래 내용을 붙여 넣습니다. 본문 칸도 Markdown으로 씁니다.

    ```markdown
    ## 요구 내용
    오늘 쓸 수 있는 예산을 입력하면 그 안에서 고를 수 있는 메뉴만 보여 준다.

    ## 근거
    - 현업 요청 2번: "예산을 넣으면 그 안에서 고를 수 있는 메뉴만 보였으면"
    - 현업 요청에서 1, 2번이 가장 급하다고 함

    ## 완료 조건
    - [ ] 예산 입력칸이 있다
    - [ ] 예산 10000을 넣으면 1만 원 넘는 메뉴가 보이지 않는다
    ```

5. 아직 등록하지 않습니다. 다음 STEP에서 오른쪽 사이드바를 채웁니다.

## STEP 4. 담당자, 라벨, 마일스톤 붙이기

이슈 작성 화면 오른쪽(화면이 좁으면 본문 아래)에 **Assignees**, **Labels**, **Projects**, **Milestone** 항목이 있습니다.

1. **Assignees**(담당자) 옆 톱니바퀴 아이콘 또는 글자를 클릭합니다. 목록에서 **내 아이디**를 클릭합니다. (아래의 `Assign yourself` 링크를 눌러도 됩니다.) 빈 곳을 클릭해 목록을 닫습니다.
2. **Labels** 옆을 클릭합니다. 목록에서 **기능**과 **우선순위-상**을 클릭해 체크합니다. 위쪽 검색칸에 `우선`처럼 일부만 입력해 찾아도 됩니다. 빈 곳을 클릭해 닫습니다.
3. **Milestone** 옆을 클릭합니다. 목록에서 **MVP**를 클릭합니다.
4. 오른쪽 사이드바에 내 프로필 사진, 라벨 2개, MVP가 표시되었는지 확인합니다.
5. 아래쪽 초록색 **Create**(만들기) 버튼을 클릭합니다. (화면에 따라 **Submit new issue**라고 되어 있을 수 있습니다.)

확인: 제목 옆에 **#1**이 붙은 이슈가 만들어지고, 제목 아래에 초록색 **Open** 표시가 보입니다. 오른쪽 사이드바에 담당자, 라벨 `기능` `우선순위-상`, 마일스톤 `MVP`가 보입니다.

!!! tip "Create more"
    **Create** 버튼 옆에 **Create more** 체크박스가 있으면, 체크하고 만들 때 작성 화면이 다시 열려서 이슈를 연달아 등록하기 편합니다.

## STEP 5. 두 번째 이슈 등록하기

STEP 3~4를 반복해 두 번째 이슈를 등록합니다.

1. **Issues** 탭 → **New issue**를 클릭합니다.
2. 제목:

    ```text
    가까운 메뉴만 보기
    ```

3. 본문:

    ```markdown
    ## 요구 내용
    회사에서 걸어갈 거리(미터)를 입력하면 그 거리 안의 메뉴만 보여 준다.

    ## 근거
    - 현업 요청 3번: "가까운 곳만 볼 수 있으면 좋겠습니다"
    - 킥오프 회의록 5. 거리: "걸어서 10분 안쪽", "비 오는 날에는 가까운 데가 더 중요"

    ## 완료 조건
    - [ ] 거리 입력칸이 있다
    - [ ] 거리 500을 넣으면 500m 넘는 메뉴가 보이지 않는다
    ```

4. 오른쪽 사이드바를 채웁니다.
    - **Assignees**: 내 아이디
    - **Labels**: **기능**, **우선순위-중**
    - **Milestone**: **MVP**
5. **Create**를 클릭합니다.

확인: **#2 가까운 메뉴만 보기** 이슈가 만들어집니다.

## STEP 6. 라벨로 걸러 보기

이슈가 수십 개가 되면 원하는 것만 골라 봐야 합니다.

1. 위쪽 **Issues** 탭을 클릭해 이슈 목록으로 갑니다. 이슈 2개가 보입니다.
2. 목록 위 검색창에는 `is:issue state:open`(열린 이슈) 같은 조건이 들어 있습니다. 검색창 안을 클릭하고 내용을 모두 지운 뒤 아래를 입력하고 ++enter++ 를 누릅니다.

    ```text
    is:issue label:기능
    ```

3. `기능` 라벨이 붙은 이슈 2개가 보입니다.
4. 이번에는 아래로 바꿔 검색합니다.

    ```text
    is:issue label:우선순위-상
    ```

5. **#1 예산으로 메뉴 거르기** 하나만 보입니다.
6. 다른 방법도 해 봅니다. 이슈 목록에서 `우선순위-중` 라벨 꼬리표를 직접 클릭하면 그 라벨로 걸러진 목록이 바로 나옵니다.
7. 검색창을 지우거나 **Issues** 탭을 다시 눌러 전체 목록으로 돌아옵니다.

확인: `label:우선순위-상`으로 검색하면 이슈가 1개만 보입니다.

| 검색 조건 | 뜻 |
|---|---|
| `is:issue` | 이슈만 (Pull Request 제외) |
| `is:open` / `is:closed` | 열린 것 / 닫힌 것 |
| `label:기능` | 기능 라벨이 붙은 것 |
| `milestone:MVP` | MVP 마일스톤에 묶인 것 |
| `assignee:@me` | 내가 담당자인 것 |

조건은 띄어쓰기로 여러 개 이어 쓸 수 있습니다. 띄어쓰기로 이은 조건은 **모두 만족하는 것만**(AND) 남깁니다. 예: `is:issue is:open label:기능 assignee:@me`는 "이슈이면서, 열려 있고, 기능 라벨이 있고, 내가 담당자인 것"입니다.

둘 중 하나만 만족해도 되게(OR) 찾으려면 괄호 안에 대문자 `OR`를 씁니다. 예: `is:issue (label:기능 OR label:질문)`

## STEP 7. 이슈 닫기

일이 끝난 이슈는 닫습니다. 연습으로 #2를 닫아 봅니다.

1. 이슈 목록에서 **가까운 메뉴만 보기**를 클릭합니다.
2. 아래로 스크롤해 댓글 입력칸으로 갑니다. 닫는 이유를 댓글로 남깁니다.

    ```text
    연습으로 닫습니다. 웹페이지에 이미 거리 입력칸이 있어 확인 완료.
    ```

3. 댓글 입력칸 아래의 **Close with comment**(댓글 남기고 닫기) 버튼을 클릭합니다. (댓글 없이 닫을 때는 버튼 이름이 **Close issue**입니다.)
4. 제목 아래 표시가 초록 **Open**에서 보라색 **Closed**로 바뀝니다.
5. 위쪽 **Issues** 탭을 클릭합니다. 목록에는 #1만 보입니다.
6. 목록 위쪽의 **Closed** 탭(숫자 1)을 클릭합니다.

확인: **Closed** 탭에 **#2 가까운 메뉴만 보기**가 보입니다. 닫힌 이슈는 지워지지 않고 이렇게 남습니다.

마일스톤 진행률도 확인합니다. **Issues** 탭 → **Milestones**를 클릭합니다.

확인: MVP가 **50% complete** (1 open, 1 closed)로 바뀌었습니다.

!!! note "닫은 이슈를 다시 열려면"
    닫힌 이슈 화면 아래쪽 **Reopen issue** 버튼을 누르면 다시 열립니다. 다음 실습 2-4에서 이 이슈를 하위 이슈로 쓰기 때문에 **지금 다시 열어 둡니다.** #2를 열고 **Reopen issue**를 클릭하세요.

## 성공하면

- [x] **Labels**에 `기능`, `질문`, `우선순위-상`, `우선순위-중`, `우선순위-하`가 있습니다.
- [x] **Milestones**에 `MVP`가 있습니다.
- [x] 이슈 #1 `예산으로 메뉴 거르기` (기능, 우선순위-상, MVP, 담당자 나)가 있습니다.
- [x] 이슈 #2 `가까운 메뉴만 보기` (기능, 우선순위-중, MVP, 담당자 나)가 있습니다.
- [x] #2를 닫았다가 다시 열었습니다. (지금은 두 이슈 모두 Open)

## 막히면

??? failure "Issues 탭이 안 보입니다"
    템플릿으로 만든 리포지토리에서 이슈 기능이 꺼져 있는 경우입니다. **Settings** → **General**에서 아래로 내려 **Features** 영역의 **Issues** 체크박스를 체크합니다.

??? failure "Label name has already been taken 이라고 나옵니다"
    같은 이름의 라벨이 이미 있습니다. 라벨 목록에서 그 라벨이 있는지 확인하고, 있으면 그대로 씁니다.

??? failure "Labels 목록에서 내가 만든 라벨이 안 보입니다"
    목록이 길어서 아래쪽에 있을 수 있습니다. Labels 목록 위쪽 검색칸에 `우선`이나 `기능`을 입력해 찾습니다. 그래도 없으면 STEP 1을 다시 확인합니다. 라벨 이름에 띄어쓰기가 들어가지 않았는지도 봅니다(`우선순위 - 상`이 아니라 `우선순위-상`).

??? failure "이슈를 이미 만들었는데 라벨이나 마일스톤을 빠뜨렸습니다"
    이슈 화면 오른쪽 사이드바의 **Labels**, **Milestone** 옆을 클릭하면 만든 뒤에도 언제든 붙이거나 뗄 수 있습니다. 바꾼 기록은 이슈 아래에 자동으로 남습니다.

??? failure "label:기능 으로 검색했는데 아무것도 안 나옵니다"
    검색창에 기존 조건(`is:open` 등)과 섞여 오타가 생긴 경우가 많습니다. 검색창을 모두 지우고 `is:issue label:기능`만 다시 입력합니다. 라벨 이름에 띄어쓰기가 있다면 `label:"우선순위 상"`처럼 큰따옴표로 감싸야 하므로, 라벨 이름은 띄어쓰기 없이 만드는 것이 편합니다.
