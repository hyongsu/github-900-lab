# 실습 2-3. 이슈 템플릿 만들기

!!! abstract "이번 실습에서 할 것"
    - 사용자 스토리 이슈 템플릿 파일 `.github/ISSUE_TEMPLATE/user-story.md`를 만듭니다.
    - New issue에서 템플릿을 골라 "혼밥 가능 표시" 사용자 스토리를 등록합니다.

**소요 시간** 약 4분  **실습 장소** 개인 연습 리포지토리 `lunch-practice`  **관련 교안** [2교시 교안](index.md#issue-template)

## 준비

- [실습 2-2](lab-2.md)를 마쳐서 라벨 `기능`과 마일스톤 `MVP`가 있어야 합니다. 템플릿이 `기능` 라벨을 자동으로 붙이기 때문입니다.
- `lunch-practice` 리포지토리 첫 화면(**Code** 탭)을 열어 둡니다.

## STEP 1. 템플릿 파일 만들기

이슈 템플릿은 정해진 폴더 `.github/ISSUE_TEMPLATE/` 안에 Markdown 파일로 만듭니다. 폴더 이름과 위치가 정확해야 GitHub가 템플릿으로 알아봅니다.

1. 리포지토리 첫 화면에서 파일 목록 위의 **Add file** 버튼을 클릭합니다.
2. **Create new file**을 클릭합니다.
3. **Name your file...** 칸에 아래 이름을 그대로 입력합니다. 대문자, 밑줄, 점, 슬래시 하나까지 똑같아야 합니다.

    ```text
    .github/ISSUE_TEMPLATE/user-story.md
    ```

    슬래시를 입력할 때마다 폴더로 바뀌어, 위쪽 경로가 `lunch-practice / .github / ISSUE_TEMPLATE /`가 되고 칸에는 `user-story.md`만 남습니다.

확인: 이름 칸 왼쪽 경로가 `lunch-practice / .github / ISSUE_TEMPLATE /`이고, 칸 안이 `user-story.md`입니다.

!!! note "`.github` 폴더는 이미 있지 않나요?"
    맞습니다. Starter에 자동 작업 설정(`.github/workflows/`)이 들어 있어서 `.github` 폴더는 이미 있습니다. 그 안에 `ISSUE_TEMPLATE` 폴더를 새로 하나 더 만드는 것입니다. 이름 앞의 점(`.`)은 "설정용 폴더"라는 관례입니다.

## STEP 2. 템플릿 내용 붙여 넣기

아래 내용을 복사해 편집 칸에 붙여 넣습니다. **첫 줄의 `---`부터** 빠짐없이 붙여 넣어야 합니다.

```markdown
---
name: 사용자 스토리
about: 누가, 무엇을, 왜 원하는지 요구사항을 씁니다
title: "[스토리] "
labels: 기능
assignees: ''
---

## 누구로서

(예: 혼자 점심을 먹는 날이 많은 팀원으로서)

## 무엇을 하고 싶다

(예: 혼밥하기 편한 메뉴를 한눈에 알아보고 싶다)

## 왜냐하면

(예: 혼자 가도 눈치 보이지 않는 식당을 찾느라 시간이 걸리기 때문이다)

## 인수 조건

- [ ] (예: 혼밥 가능한 메뉴 카드에 "혼밥 가능" 표시가 보인다)
- [ ] 
```

붙여 넣은 내용은 두 부분으로 나뉩니다.

| 부분 | 줄 | 뜻 |
|---|---|---|
| 머리말 (front matter) | `---`와 `---` 사이 | 템플릿 설정. 이슈 본문에는 나오지 않습니다 |
| | `name: 사용자 스토리` | 템플릿 고르는 화면에 보일 이름 |
| | `about: ...` | 템플릿 이름 아래에 보일 설명 |
| | `title: "[스토리] "` | 새 이슈 제목 칸에 미리 들어갈 글자. 뒤에 띄어쓰기가 있어 바로 이어 쓸 수 있습니다 |
| | `labels: 기능` | 이 템플릿으로 만든 이슈에 자동으로 붙을 라벨 |
| | `assignees: ''` | 자동 담당자. 비워 둡니다 |
| 본문 양식 | 두 번째 `---` 아래 | 새 이슈 본문 칸에 미리 채워질 내용 |
| | `## 누구로서` | 이 기능을 쓰는 사람 |
| | `## 무엇을 하고 싶다` | 그 사람이 원하는 것 |
| | `## 왜냐하면` | 원하는 이유. 우선순위를 정할 때 근거가 됩니다 |
| | `## 인수 조건` | **무엇이 되면 "다 됐다"고 받아들일지** 적은 확인 목록 |

!!! note "인수 조건은 무엇인가요?"
    인수 조건(acceptance criteria)은 요청한 쪽이 결과물을 **받아들이는(인수하는) 기준**입니다. "혼밥 표시를 해 주세요"만 쓰면 개발자는 어디에 어떤 모양으로 넣어야 끝인지 알 수 없고, 다 만든 뒤에 "이게 아닌데요"가 나옵니다. 그래서 만들기 전에 "혼밥 가능한 메뉴 카드에 '혼밥 가능' 표시가 보인다"처럼 **화면에서 눈으로 확인할 수 있는 문장**으로 미리 합의해 둡니다.

    | 누가 | 인수 조건을 어떻게 쓰나 |
    |---|---|
    | 개발자 | 이것만 맞추면 끝이라는 **작업 범위** |
    | BA, 리뷰어 | 결과물이 요구를 충족했는지 하나씩 체크하는 **검토 기준** (6교시 팀 실습에서 BA가 이 기준으로 PR을 검토합니다) |
    | PO, 요청자 | 배포된 화면에서 직접 확인하는 **승인 기준** |

    템플릿에 `## 인수 조건`을 넣어 두는 이유는, 요구를 쓸 때마다 이 기준을 빠뜨리지 않게 하려는 것입니다. 4교시에 우선순위와 함께 다시 다룹니다.

확인: 편집 칸 첫 줄이 `---`이고, 일곱째 줄도 `---`입니다.

!!! warning "머리말에서 자주 하는 실수"
    - 첫 줄 `---` 위에 빈 줄이 있으면 머리말로 인식하지 않습니다. 첫 줄이 반드시 `---`여야 합니다.
    - `name:` 처럼 쌍점 뒤에 **띄어쓰기**가 있어야 합니다.
    - `labels:`에 쓴 라벨이 리포지토리에 없으면 이슈에 라벨이 붙지 않습니다. 실습 2-2에서 만든 `기능`과 글자가 같아야 합니다.

## STEP 3. 커밋하기

1. 오른쪽 위 **Commit changes...** 버튼을 클릭합니다.
2. **Commit message**를 아래처럼 씁니다.

    ```text
    사용자 스토리 이슈 템플릿 추가
    ```

3. **Commit directly to the `main` branch**를 확인하고 **Commit changes**를 클릭합니다.

확인: 파일 화면에 머리말이 **표 모양**(name, about, title, labels, assignees 칸)으로 보이고, 그 아래에 본문 양식이 보입니다.

## STEP 4. 템플릿으로 이슈 등록하기

1. 위쪽 탭에서 **Issues**를 클릭합니다.
2. 초록색 **New issue** 버튼을 클릭합니다.
3. 이번에는 바로 작성 화면이 아니라 **템플릿 고르는 화면**이 나옵니다. **사용자 스토리**(설명: 누가, 무엇을, 왜 원하는지 요구사항을 씁니다)와 **Blank issue**(빈 이슈)가 보입니다.
4. **사용자 스토리**를 클릭합니다. (화면에 따라 오른쪽의 **Get started** 버튼을 클릭합니다.)
5. 작성 화면이 열립니다. 아래를 확인합니다.
    - 제목 칸에 `[스토리] `가 미리 들어 있습니다.
    - 본문 칸에 `## 누구로서`, `## 무엇을 하고 싶다`, `## 왜냐하면`, `## 인수 조건`이 미리 들어 있습니다.
    - 오른쪽 **Labels**에 `기능`이 이미 붙어 있습니다.
6. 제목 칸의 `[스토리] ` 뒤를 클릭하고 이어서 입력합니다.

    ```text
    혼밥 가능 표시
    ```

    제목 전체가 `[스토리] 혼밥 가능 표시`가 됩니다.

7. 본문 칸의 내용을 모두 지우고(++ctrl+a++ 또는 ++cmd+a++ 후 ++delete++) 아래로 바꿔 붙여 넣습니다. 양식의 괄호 예시를 실제 내용으로 채운 것입니다.

    ```markdown
    ## 누구로서

    혼자 점심을 먹는 날이 많은 팀원으로서

    ## 무엇을 하고 싶다

    혼밥하기 편한 메뉴를 한눈에 알아보고 싶다

    ## 왜냐하면

    혼자 가도 눈치 보이지 않는 식당을 찾느라 시간이 걸리기 때문이다

    ## 인수 조건

    - [ ] 혼밥 가능한 메뉴 카드에 "혼밥 가능" 표시가 보인다
    - [ ] 혼밥 불가능한 메뉴 카드에는 표시가 없다

    근거: 현업 요청 5번, 킥오프 회의록 6. 기타 (이민호 "혼밥 가능한지 표시는 꼭")
    ```

8. 오른쪽 사이드바를 채웁니다.
    - **Assignees**: 내 아이디
    - **Labels**: `기능`은 이미 있음. **우선순위-하** 추가
    - **Milestone**: **MVP**
9. **Create**를 클릭합니다.

확인: **#3 [스토리] 혼밥 가능 표시** 이슈가 만들어지고, 라벨 `기능` `우선순위-하`, 마일스톤 `MVP`가 붙어 있습니다.

만들어진 이슈 본문의 인수 조건 체크박스 중 첫 번째를 **클릭**해 봅니다. 체크 표시가 생깁니다. 웹페이지에 이미 혼밥 가능 배지가 있으니 사실이기도 합니다.

확인: 이슈 목록에서 #3 제목 아래에 `1 of 2` 같은 체크박스 진행 표시가 보입니다.

!!! note "왜 템플릿을 파일로 만드나요?"
    템플릿은 리포지토리에 커밋된 **파일**이라서 Git이 관리합니다. 그래서 누가 언제 양식을 바꿨는지 History로 남고, 리포지토리를 복제하면 양식도 함께 따라갑니다. 반면 템플릿으로 만든 이슈 #3은 GitHub 서비스가 관리하는 데이터입니다. 교안의 [Git과 GitHub가 관리하는 영역](index.md#git-vs-github-data)을 떠올려 보세요.

## 성공하면

- [x] 리포지토리에 `.github/ISSUE_TEMPLATE/user-story.md` 파일이 있습니다.
- [x] **New issue**를 누르면 템플릿 고르는 화면에 **사용자 스토리**가 보입니다.
- [x] 이슈 #3 `[스토리] 혼밥 가능 표시`에 `기능` 라벨이 자동으로 붙어 있고, 마일스톤은 `MVP`입니다.

## 막히면

??? failure "New issue를 눌러도 템플릿 고르는 화면이 안 나오고 바로 빈 작성 화면이 나옵니다"
    템플릿 파일 위치나 이름이 틀린 경우입니다. 리포지토리 첫 화면에서 **.github** 폴더를 열어 `ISSUE_TEMPLATE` 폴더가 있는지, 그 안에 `user-story.md`가 있는지 확인합니다. 흔한 실수는 `issue_template`(소문자), `ISSUE-TEMPLATE`(빼기 기호), `.github`의 점 빠뜨림입니다. 틀렸다면 파일을 열고 연필 아이콘을 눌러 이름 칸을 고친 뒤 커밋하면 위치가 옮겨집니다. 커밋 직후라면 브라우저를 새로고침하고 다시 **New issue**를 누릅니다.

??? failure "템플릿 목록에 사용자 스토리 대신 user-story.md 라는 이름이 보이거나, 제목과 라벨이 안 채워집니다"
    머리말을 인식하지 못한 경우입니다. 파일 첫 줄이 `---`인지(위에 빈 줄이 없는지), 머리말 끝에도 `---`가 있는지, `name:` 뒤에 띄어쓰기가 있는지 확인합니다.

??? failure "이슈에 기능 라벨이 자동으로 안 붙습니다"
    리포지토리에 `기능` 라벨이 없거나 이름이 다른 경우입니다. **Issues** → **Labels**에서 `기능`이 정확히 있는지 확인합니다. 이미 만든 이슈에는 오른쪽 **Labels**에서 직접 붙이면 됩니다.
